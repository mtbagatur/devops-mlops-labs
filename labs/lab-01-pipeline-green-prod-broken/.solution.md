# Lab 01 — Hidden solution (spoiler)

## Root cause
- `/etc/pricing-api/pricing.env` was never managed by the pipeline. `DATABASE_URL` had been added by hand months ago.
- Last night (Sep 29 23:10) the config-management baseline run (Ansible role `app_env`) re-templated `pricing.env` from a template containing only non-secret keys, silently dropping the hand-added line. The running process kept its old environment, so nothing broke until today's deploy restarted the service.
- Azure DevOps secret variables are **not** exported to script environments automatically and are never written to the host. The variable group value never reached systemd.
- The pipeline is green because: `systemctl restart` returns 0 as soon as the start job is queued (Type=simple), and the healthcheck runs `curl -s` without `--fail`, so a 502 still exits 0.

## Simulated environment facts (keep consistent)
- `ls -l /etc/pricing-api/` → `pricing.env` root:root 0644, modified `Sep 29 23:10`; `pricing.env.bak.2026-09-29` does not exist.
- `journalctl -u pricing-api -n 50` → repeated start/exit; `Restart=always` with default StartLimitBurst=5 → `start-limit-hit` after 5 tries.
- `grep -r pricing.env /etc/ansible` or `/var/log/ansible.log` shows the Sep 29 run changed the file.
- `readlink /opt/pricing-api/current` → `/home/azagent/_work/3/a/release` (agent staging directory!).
- `curl -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/health` → connection refused; through NGINX → 502.

## Reference sequence
1. `systemctl status pricing-api`, `journalctl -u pricing-api -n 100 --no-pager` — confirm crash reason, restart loop, start-limit.
2. `systemctl cat pricing-api` — which EnvironmentFile; `ls -l` + `stat` on it — when it changed.
3. Check who changed it (ansible log / `last` / config management).
4. `readlink -f /opt/pricing-api/current`, `ls` it — what the symlink points to.
5. Immediate fix without echoing the secret:
   `sudo install -m 600 -o root -g root /dev/null /etc/pricing-api/secrets.env` and append the value via `read -rs` + `printf ... | sudo tee -a ... >/dev/null`, or a `systemctl edit` drop-in with `EnvironmentFile=` for the secret file; value fetched from Key Vault (`az keyvault secret show --query value -o tsv` piped, never printed).
6. `sudo systemctl reset-failed pricing-api && sudo systemctl restart pricing-api`, `systemctl is-active`, `ss -ltnp | grep 8080`, `curl -fsS http://127.0.0.1:8080/health`, then through NGINX.
7. Fix the config-management template so it no longer overwrites, or move secrets out of that file.

## Pipeline redesign
- Pull the secret from Azure Key Vault (AzureKeyVault@2 task or variable group linked to Key Vault), map it explicitly with `env: DATABASE_URL: $(DATABASE_URL)`, write it on the host to a root-owned 0600 file used as a second `EnvironmentFile=` (or systemd credentials `LoadCredential=`). Never `echo` it; never pass it as a command-line argument.
- Better: the host fetches it itself at start (managed identity + Key Vault) so the pipeline never handles it.
- App should fail fast on startup (it does) and systemd unit should use `Type=notify`/healthcheck-based readiness.

## Making the pipeline honest
- `curl --fail --retry 10 --retry-delay 3 --retry-all-errors` against `127.0.0.1:8080/health` and the public URL; `systemctl is-active --quiet` after a short wait; fail the stage otherwise.
- Automatic rollback to the previous release symlink on failed health check.

## Bonus risks in the deploy step
- Symlink points into the agent's `$(Build.ArtifactStagingDirectory)`, which is cleaned on the next run → production code disappears. Releases must be copied to `/opt/pricing-api/releases/<build-id>` and the symlink switched atomically.
- `systemctl stop` before swapping = guaranteed downtime; no rollback path; `daemon-reload` without unit change is pointless; venv built on the agent may not match the server's Python; `Restart=always` hides crash loops until start-limit.

## Rubric (10)
- 2 ordered diagnosis (status → journal → unit → env file → why it changed)
- 2 immediate fix that does not leak the secret
- 2 root cause: secret never delivered by design + overwritten file
- 2 pipeline redesign (Key Vault, explicit env mapping, 0600 file / credentials)
- 1 honest health gate (`--fail`, retries, rollback)
- 1 bonus risk (staging-directory symlink or stop-then-swap downtime)
