# Lab 06 — Hidden solution (spoiler)

## Root cause
- Cluster (AKS) has 3 nodes: `aks-system-…-0` (no GPU, no `workload` label) and two `Standard_NC6s_v3` nodes in pool `gpuinfer` (1× V100 each, label `workload=gpu-inference`).
- Each GPU is allocated to one of the two old pods. `maxSurge: 1, maxUnavailable: 0` requires a 3rd GPU for the surge pod; none exists → Pending forever → `helm --wait` times out. Rollout deadlock, not a bug in the pod spec.
- GPU node pool has cluster autoscaler **disabled** (min=max=2). Regional NCv3 quota allows 1 more node (12 vCPU free).

## Simulated environment facts (keep consistent)
- `kubectl describe node <gpu-node>` → `nvidia.com/gpu: 1` capacity/allocatable, `Allocated: nvidia.com/gpu 1 (100%)`.
- `kubectl get nodes -L workload,agentpool` → as above.
- `az aks nodepool show -n gpuinfer` → `enableAutoScaling: false, count: 2`.
- `az vm list-usage -l westeurope --query "[?name.value=='standardNCSv3Family']"` → current 12, limit 24.
- Traffic: peak 180 req/s; one pod handles ~110 req/s at p95 < 200 ms. Current time 10:40, near daily peak (11:00–14:00). HPA min 2 max 2. PDB minAvailable 2.
- The Pending pod is from new RS; old RS 2/2.

## Reference sequence
1. `kubectl describe pod <pending>` events; `kubectl get nodes -L workload`; `kubectl describe node` → GPU allocation; `kubectl get pods -o wide` → who holds the GPUs.
2. Establish production facts: traffic vs single-pod capacity, PDB, HPA, peak hours, SLO.
3. Options:
   - a) Temporarily scale GPU pool to 3 (`az aks nodepool scale --node-count 3`, quota allows) → rolling update proceeds with zero capacity loss → scale back to 2 afterwards. Preferred during peak.
   - b) `maxSurge: 0, maxUnavailable: 1` → runs on half capacity during rollout; only acceptable off-peak and must relax PDB minAvailable 2 → would otherwise block eviction too.
   - c) Blue/green on a separate temporary GPU node pool.
4. Roll forward via Helm (not kubectl patch), `helm upgrade --wait --timeout` long enough for node provisioning (~8–10 min) + model load.
5. Verify rollout, GPU utilisation (`nvidia-smi` via DCGM exporter), latency, scale back pool, check nothing Pending.

## Prevention
- Pre-deploy capacity check in the pipeline (free `nvidia.com/gpu` on matching nodes ≥ maxSurge), or autoscaler with max ≥ replicas + surge.
- Strategy chosen deliberately per workload; documented release window.
- Consider GPU time-slicing/MIG for inference, or node pool headroom.
- Helm timeout aligned with node provisioning; automatic rollback on failure.
