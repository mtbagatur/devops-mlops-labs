# Lab 05 — Hidden solution (spoiler)

## Root cause (two independent problems)
1. **Config drift:** the deploy task never passes `-f values-prod.yaml`. The chart's `values.yaml` defaults apply (requests 256Mi, limits 512Mi), and the variable group sets `MEMORY_LIMIT=512Mi`, which would override the limit even if prod values were passed. Repo values have never been effective in prod.
2. **Real memory growth:** model v2.4.0 artifact grew from 140 MB (v2.3.0) to 610 MB (new embedding layer, saved as float32 instead of float16). Load peak ≈ 1.3 GiB, steady state ≈ 900 MiB. Old pods use ≈ 380 MiB. So even 1Gi from values-prod.yaml is not enough.

## Simulated environment facts (keep consistent)
- `helm get values prediction-api -n ml-prod` → `image.tag: v2.4.0`, `resources.limits.memory: 512Mi` (user-supplied); no requests override.
- `helm get values --all` → requests memory 256Mi (chart default).
- Variable group: `MEMORY_LIMIT=512Mi` (set 8 months ago).
- `kubectl top pod -n ml-prod -l app=prediction-api` → old pods ~380Mi / 600m CPU.
- MLflow / model registry: v2.3.0 model.pkl 140 MB, v2.4.0 model.pkl 610 MB, dtype float32.
- Local `docker run --memory=2g` of the v2.4.0 image + `docker stats` → peak 1.31GiB during load, 910MiB steady.
- Node allocatable: 3 nodes × 7.5 GiB, ~3 GiB free per node.
- `dmesg`/node journal: `memory cgroup out of memory: Killed process ... (gunicorn)`.

## Reference sequence
1. `kubectl describe pod` / `kubectl get pod -o jsonpath='{.status.containerStatuses[0].lastState}'` → OOMKilled at limit.
2. `helm get values` (user-supplied vs `--all`) → which source produced 512Mi; compare with pipeline args and variable group.
3. `kubectl top` on old pods; inspect model artifact size; reproduce load locally with `docker stats` to measure peak.
4. Fix: pipeline passes `-f values-prod.yaml`; remove `--set-string resources.limits.memory` (or delete MEMORY_LIMIT); set requests ≈ steady state (1Gi), limit ≥ peak + headroom (2Gi); check node allocatable and quota. Optionally fix model export (float16) with the ML team.
5. Deploy, `kubectl rollout status`, watch `kubectl top`, confirm restarts 0, latency/error dashboards, old RS → 0.

## Prevention
- Single source of truth for values; no ad-hoc `--set` overrides from variable groups; `helm template`/`helm diff` output in PR.
- ML pipeline gate: model size and load-memory benchmark recorded in the registry; fail if it exceeds the deployment's budget.
- Startup probe with enough time for model load; alert on OOMKilled.

## Rubric (10)
- 1 hypothesis covers both config drift and memory growth
- 2 proves where 512Mi/256Mi came from (helm get values, pipeline args, variable group)
- 2 measures real memory need instead of guessing (top, artifact size, local repro)
- 2 correct, safe resource change + pipeline fix
- 1 does not delete healthy pods; verifies capacity on nodes
- 1 verification after rollout
- 1 prevention (model size gate, values governance)
