# Lab 04 — Hidden solution (spoiler)

## Root cause
- Helm received and rendered `15`; the ConfigMap is live with `15`.
- A Deployment only creates a new ReplicaSet when `.spec.template` (the PodTemplate) changes — its hash becomes `pod-template-hash`. Changing a ConfigMap does not change the PodTemplate, so nothing rolled.
- `envFrom` values are copied into the process environment at container start and never refresh. A mounted ConfigMap volume refreshes the files eventually (kubelet sync, ~1 min; never with `subPath`), but the app would still have to re-read the file — so a volume alone would not have fixed this app.
- The smoke test checked "service responds", not "service runs the intended config".

## Reference sequence
1. `helm history order-api -n shop`, `helm get values order-api -n shop` (sees 15), `helm get manifest ... | grep -A3 PAYMENT` (rendered 15).
2. `kubectl get cm order-api-config -n shop -o yaml` (live 15).
3. `kubectl get deploy order-api -n shop -o jsonpath='{.metadata.generation} {.status.observedGeneration}'` — generation unchanged by today's upgrade.
4. `kubectl get rs -n shop -l app=order-api` — single RS, age = yesterday; `pod-template-hash` label.
5. `kubectl exec <pod> -- printenv PAYMENT_TIMEOUT` → 5; pod start time older than the ConfigMap update.
6. Immediate: `kubectl rollout restart deploy/order-api -n shop` (adds `kubectl.kubernetes.io/restartedAt` annotation → new RS, maxSurge 1/maxUnavailable 0 keeps capacity). Note this drifts from Helm until the chart fix is deployed.
7. IaC fix in `templates/deployment.yaml`:
   ```yaml
   template:
     metadata:
       annotations:
         checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
   ```
   Then `helm upgrade order-api ./chart/order-api -n shop -f values-prod.yaml --wait`.
8. Verify: `kubectl rollout status`, new RS 4/4, old RS 0, `printenv` 15 in each pod, `wget -qO- http://order-api:8080` shows 15, `helm get manifest` contains the checksum annotation.

Alternatives worth mentioning: immutable, versioned ConfigMap names (`order-api-config-<hash>`), Kustomize configMapGenerator, Reloader (stakater) controller.

## Pipeline
Smoke test should assert the effective config/version (e.g. `/info` or `/version` endpoint exposing config hash, or compare `printenv` / rendered hash), and the pipeline should fail when `helm upgrade` changes a ConfigMap without producing a new ReplicaSet.

## Rubric (10)
- 1 proves Helm received 15 (`helm get values`/history)
- 1 proves rendered + live ConfigMap
- 2 explains PodTemplate → pod-template-hash → ReplicaSet
- 1 envFrom vs volume (refresh, subPath, app must re-read)
- 1 safe immediate rollout (rollout restart, maxSurge/maxUnavailable)
- 2 checksum annotation deployed via Helm (verify.sh checks 6–7)
- 1 full verification
- 1 better smoke test / pipeline gate
