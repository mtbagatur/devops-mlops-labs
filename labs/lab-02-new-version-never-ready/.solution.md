# Lab 02 — Hidden solution (spoiler)

## Root cause
- v2.8.0 is the first version that calls the feature store; v2.7.x never did, so old pods are unaffected.
- Namespace `ml-platform` has a default-deny ingress NetworkPolicy plus `allow-feature-store-clients`, which only admits pods from namespaces labelled `feature-store-access: "true"`. Namespace `production` lacks that label. Packets are dropped → TCP **timeout** (not connection refused).
- DNS, Service, Endpoints and the feature-store pods are all healthy.
- Aggravating design flaw: `maxSurge: 0, maxUnavailable: 50%` — the rollout removed half of production capacity before proving the new version could become Ready.

## Simulated environment facts (keep consistent)
- `nslookup feature-store.ml-platform.svc.cluster.local` from the pod → resolves to ClusterIP 10.96.142.18.
- `nc -zvw3 feature-store.ml-platform.svc.cluster.local 9000` → timeout. Same against a pod IP (10.244.3.27:9000) → timeout.
- `kubectl get svc,endpoints -n ml-platform feature-store` → port 9000 → targetPort 9000, 3 endpoints.
- `kubectl get pods -n ml-platform -l app=feature-store` → 3/3 Running Ready.
- From a debug pod in `ml-platform`: `curl feature-store:9000/health` → 200.
- `kubectl get networkpolicy -n ml-platform` → `default-deny-ingress`, `allow-feature-store-clients` (namespaceSelector `feature-store-access: "true"`).
- `kubectl get ns --show-labels` → `recsys-staging` has the label (staging worked), `production` does not.
- CNI: Calico (enforces policies).

## Reference sequence
1. Do not roll back yet; capacity is 2/4 — first decide: pause (`kubectl rollout pause`) or `helm rollback` to restore 4 replicas if traffic needs it.
2. In-pod: `nslookup` (DNS ok) → `nc`/`curl -v --max-time 5` to Service and to a pod IP (timeout on both → not Service/kube-proxy, likely policy or network).
3. `kubectl get svc,endpointslices -n ml-platform`, pods Ready, test from inside `ml-platform` (works → server healthy).
4. `kubectl get networkpolicy -A`, `kubectl describe networkpolicy -n ml-platform` → selector mismatch.
5. Fix through IaC (platform team's repo): label `production` namespace or add an explicit policy rule for `recommendation-api` pods (prefer namespace+podSelector, least privilege). Coordinate with ml-platform owners.
6. Verify: `nc` succeeds, readiness 200, `kubectl rollout status` completes 4/4, old RS 0, error rate/latency dashboards normal.

## Prevention
- Rollout: `maxSurge: 1, maxUnavailable: 0` (or 25%/0).
- Dependency/egress requirements declared with the chart; staging must mirror prod policies (staging namespace was labelled by hand).
- Readiness shouldn't hard-fail on a non-critical dependency forever; consider degraded mode + startup checks.
- Pipeline: `kubectl rollout status` with sensible timeout + automatic `helm rollback`.
